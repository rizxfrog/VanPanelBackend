Section 3 — 多级记忆系统

短期记忆 + 长期记忆 + 可选 RAG，三层架构

三层记忆架构

L1 — 工作记忆（已有）
• 存储：MySQL (agent_sessions + agent_messages)
• 范围：当前会话的历史消息（默认 20 条）
• 已实现：service.loadHistory() 加载到 ReAct 上下文
• 增强项：增加滑动窗口 + 摘要压缩（长会话不爆 context）
↕ 摘要后沉淀为长期记忆
L2 — 长期记忆（新增）
• 存储：MySQL (user_memories) + 可选 pgvector (向量化)
• 内容：
  • 用户偏好 — "该用户偏好简洁回复" / "该用户经常排查磁盘问题"
  • 操作模式 — "过去 N 次清理日志，都是清理 /var/log/nginx/*"
  • 知识条目 — "上次排查到 PID 1234 是内存泄漏进程"
  • 解决方案 — "磁盘满→ lsof 找大文件→ 清理" 的成功链路
• 写入时机：
  • 会话结束后自动提取关键信息并写入（异步）
  • 审批通过的操作记录（表示安全且有效）
• 读取：② 上下文增强阶段，按语义相似度检索相关长期记忆
↕ 可选开启
L3 — RAG 知识库（新增，可配置开关）
• 存储：外部向量库（Milvus / pgvector / Redis Vector）
• 内容：
  • 运维手册 — 内部 Wiki、标准操作流程
  • 系统文档 — 麒麟 OS 手册、内核参数说明
  • 故障案例 — 历史告警 → 根因 → 处理方案的映射
  • 知识图谱 — 故障-原因-解决方案的结构化关系
• 接入方式：配置文件中设置 rag.enabled=true + 向量库连接信息
• 检索：② 上下文增强阶段，与长期记忆并列检索，合并注入 Agent 上下文

记忆生命周期

写入：
  会话中 → agent_messages (实时)
  会话结束 → LLM 提取摘要 → user_memories (异步, MemoryExtractor)
  审批过的高危操作 → user_memories + 可选 RAG 入库
读取：
  ② 上下文增强 → 并发检索 L1(MySQL) + L2(MySQL/向量) + L3(向量库, 可选)
  结果合并去重 → 注入 system prompt 或作为附加工具
淘汰：
  L1: 会话删除时级联删除
  L2: 按时间/重要性评分淘汰，保留最近 30 天高价值条目
  L3: 由外部知识库管理，Agent 不负责淘汰

与现有代码的关系

  • L1 已有，只需增加滑动窗口 + 摘要压缩
  • L2/L3 新增，挂载在 ② 上下文增强阶段
  • 不改变 ③ Agent 推理的接口，只改变喂入的上下文

实现时可降级

  • 初期 L2 可以不接向量库，纯 MySQL LIKE 检索
  • RAG 默认关闭，不阻塞核心功能
  • 后期逐步升级：MySQL → pgvector → 专用向量库
