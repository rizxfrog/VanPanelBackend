Section 4 — 三层可扩展体系

MCP 插件 · Skill 编排 · SPI 扩展点 · 远程 Agent

扩展体系全景

面向不同角色的三层扩展
Layer 1 — MCP 插件（已有基础）
面向：第三方开发者
形式：独立进程，stdio/SSE/HTTP 协议
已有：LocalMCP + RemoteMCP + 插件市场
增强：增加远程节点 Agent（见下方）
Layer 2 — Skill 编排（新增）
面向：运维人员 / 领域专家
形式：YAML 声明式工作流或 Lua 脚本
典型 Skill：
  • "一键巡检" — 串行调用 proc.ps + disk.df + sys.free + net.ss 生成报告
  • "故障自愈" — 检测 → 诊断 → 修复 → 验证 四步流程
  • "日志分析" — tail 关键日志 → grep 异常 → 总结报告
Layer 3 — SPI 扩展点（新增）
面向：平台开发者
形式：Go Interface
  • IntentAnalyzer — 自定义意图分析策略
  • GuardRule — 自定义安全规则
  • MemoryProvider — 自定义记忆存储后端
  • Notifier — 自定义告警通知通道
  • AuditWriter — 自定义审计日志格式
Skill 定义示例 (YAML)
skill:
  name: health-check
  display: "一键巡检"
  description: "全面检查系统健康状态"
  risk: low
  steps:
    - tool: proc.ps
      params: {top: 10}
      output: process_report
    - tool: disk.df
      params: {}
      output: disk_report
    - tool: sys.free
      params: {}
      output: memory_report
    - tool: net.ss
      params: {state: listening}
      output: network_report
    - tool: sys.uptime
      params: {}
      output: uptime_info
  aggregate:
    type: llm_summary
    prompt: |
      根据以下巡检数据生成健康报告：
      进程: {{process_report}}
      磁盘: {{disk_report}}
      内存: {{memory_report}}
      网络: {{network_report}}
      运行时间: {{uptime_info}}

远程 Agent 节点

🖥 主控节点 (VanPanelBackend)
MCP Remote Agent
部署在目标服务器上的
轻量 Go 进程（5MB）

暴露 MCP 端点：
• os.exec
• os.file.read/write
• os.service.manage
• os.docker.inspect

连接方式：SSE/WS 长连接
SSH 直连（兼容）
无 Agent 场景的降级方案

已有 pkg/ssh/
通过 SSH 下发命令

限制：无实时感知能力
仅做命令执行
远程数据库
MCP 插件连接远程 DB

• MySQL MCP Server
• Redis MCP Server
• Prometheus MCP

通过 MCP 协议统一暴露
主控 Agent "看到" 远程节点的工具，就像本地工具一样透明调用

关键设计原则

  • MCP 已可用 — 远程 Agent 本质就是 RemoteMCP 的一种实例
  • Skill 不新增代码执行引擎 — 复用现有 ToolManager 调度
  • SPI 全部是 Go Interface — 无运行时开销，编译期检查
  • 所有扩展都受 ④ Guard 审查管道保护

比赛提交策略

  • MCP + SPI 核心基础必须实现
  • Skill 编排：先实现硬编码的 3-5 个 Skill 做演示
  • YAML Skill 解析器 + 远程 Agent 做加分项，不阻塞核心交付
