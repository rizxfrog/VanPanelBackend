Section 1 — 整体 Pipeline 架构

Agent 处理请求的 6 阶段分层管道，每层可独立替换

Pipeline 流程图

👤 用户自然语言指令
│
① 意图分析 + 注入防护
• 检测 Prompt Injection（角色劫持、指令覆盖、越狱）
• 意图分类：信息查询 / 状态感知 / 操作执行 / 危险操作
• 调用独立的安全模型做初步语义分析
│
② 上下文增强（记忆系统）
• 加载短期记忆：当前会话历史消息（已有）
• 加载长期记忆：用户偏好、历史模式、知识图谱
• 可选 RAG 检索：运维文档、系统手册、历史故障案例
│
③ Agent 推理（ReAct 循环）
• 思考 → 选择 Tool → 执行 → 观察 → 再思考
• 已有的 streaming/sync 两条路径保持不变
• 每次 Tool 调用前，结果要经过 ④ Guard 审查
│
④ Guard 安全审查管道
• 第一关：规则引擎（已有）— 正则黑名单 + 路径保护
• 第二关：独立审计模型 — LLM 语义分析工具调用参数
• 第三关：最小权限检查 — 当前用户是否有权执行该操作
• 输出：放行 / 需审批 / 拦截
│
⑤ 最小权限代理执行
• 非 root 账户运行核心运维动作
• 高危操作走审批流（human-in-the-loop）
• 本地执行 / SSH 远程执行 / MCP 远程 Agent 执行
│
⑥ 审计记录 — 全链路事件写入审计日志，支持回溯

关键设计决策

每层都是 Go 接口

  • IntentAnalyzer 接口 — 可切换注入检测策略
  • MemoryProvider 接口 — 可切换记忆存储后端
  • GuardChain 接口 — 可编排多层审查规则
  • ToolExecutor 接口 — 可切换本地/远程执行方式

与现有代码的关系

  • ③ Agent 推理 — 复用现有 textReActLoop + ReAct agent
  • ④ Guard 第一关 — 复用现有 risk/evaluator.go
  • ⑥ 审计记录 — 复用现有 audit/memory.go
  • 新增代码主要在第 ①②④ 层
